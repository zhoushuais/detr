二、P2 做了哪两件事,各自结论
P2 你试了两个独立机制,代码都写得很扎实(零初始化安全网、config 开关、诊断脚本齐全),但实验都证明无效:

机制 1:Dynamic Bins(动态深度桶)
想法:每张图自适应分深度桶,不用全图共享的固定 LID。
试了两版:自由 softmax 版 → 桶塌缩(80 桶里 60 个挤死在 56-60m);改成 tanh 有界版 → 塌缩修好了,但 per-image 又被 tanh 饱和压平,变成一个"全局重调的静态桶"。
AP:三列(Car Mod / Ped Hard / Cyc Hard)全落在 baseline 噪声带里,零增益。
根因(已坐实):bin 中心只通过 weighted_depth → 深度位置编码 + 前景深度图 aux loss 间接影响 decoder;最终 3D 框深度走的是独立的 per-query depth_embed(mean, logσ) 头,bins 这个杠杆根本够不到它。
机制 2:几何深度 σ 加权融合
想法:把 depth_ave 里 (回归+几何+深度图)/3 的朴素平均,换成按不确定性逆方差加权。
踩了一个大坑:首版无门 → 整个检测器崩了(Car Mod 10.9,2D bbox 从 89 崩到 40),因为几何深度耦合了预测的 2D 框高,init 时是垃圾却被赋予 0.999 权重 + loss 放大 3602×。
修了两轮:零初始化 sigmoid 门 → 门焊死没动(等于又跑了遍 baseline);改 clamp-linear 门 + loss-σ 解耦 → 安全且门能动了。
最新状态:clamp-linear 版改完了,但 P2_DBDU_Summary §11.7 末尾还停在"下次重训先跑 diagnose"——我没看到这一版的 AP 结果进实验表。这是 P2 唯一一个可能还没收口、值得再看一眼的点。
