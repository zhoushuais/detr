# 分档评测与效率统计使用说明

## 1. best epoch 选择标准

正式实验统一使用 KITTI validation 集的 `Car Moderate AP_R40 3D` 选择每次训练的唯一 best epoch。Pedestrian、Cyclist 以及各尺寸/距离分档结果不参与 checkpoint 选择。

完整模型分支的配置为：

```yaml
dataset:
  writelist: ['Car', 'Pedestrian', 'Cyclist']
  best_selection_metric: 'car_moderate_3d_r40'
```

`writelist` 必须包含三类，否则不是三类联合训练。`best_selection_metric` 只决定 `checkpoint_best.pth` 的选择规则，不改变训练类别。

各现有分支的原始状态：

| 实验 | 分支 | 原始 best 规则 | 重训前处理 |
|---|---|---|---|
| Baseline | `main` | Car Moderate | 保留选模代码，将 `writelist` 改为三类 |
| SCA-FPN | `p1-sca-fpn` | Car Moderate | 无需改选模代码 |
| ACDP Head | `P2` | Car Moderate | 无需改选模代码 |
| SCA-FPN + ACDP Head | `p1-p2-combined` | 三类 Moderate 均值 | 改为 Car Moderate |
| 完整模型 | `codex/p3-scale-aware-depth-loss` | 三类 Moderate 均值 | 改为 Car Moderate |

训练器中 `cur_result > best_result` 的代码不需要改。`cur_result` 来自 `KITTI_Dataset.eval()`，因此应在数据集评测函数中返回 Car Moderate 指标。

为减少不同分支的环境与评测代码差异，推荐在包含全部三个模块的最新分支上，通过配置开关重训五组实验：

| 实验 | `use_sca_fpn` | `use_cop` | `use_scale_aware_depth_loss` |
|---|---:|---:|---:|
| Baseline | `False` | `False` | `False` |
| SCA-FPN | `True` | `False` | `False` |
| ACDP Head | `False` | `True` | `False` |
| SCA-FPN + ACDP Head | `True` | `True` | `False` |
| 完整模型 | `True` | `True` | `True` |

除上述三个开关外，数据划分、随机种子、训练轮数、数据增强、评测阈值和 best epoch 规则必须保持一致。

## 2. 训练和推理

每个配置独立训练三次，每次改变 `random_seed` 并使用独立的 `trainer.save_path`，避免 checkpoint 和预测文件相互覆盖。

```bash
python tools/train_val.py --config configs/monodetr.yaml
```

训练时每个评测 epoch 都会输出三类结果，并使用 Car Moderate AP_R40 3D 更新 `checkpoint_best.pth`。

分档评测必须读取逐图 KITTI 预测文件，而不是读取训练日志。对 best checkpoint 完成验证集推理后，默认预测目录为：

```text
<save_path>/monodetr/outputs/data/
```

目录中应存在与 validation split 一一对应的 `000000.txt` 格式预测文件。

## 3. 尺寸和距离分档评测

默认分档为：

- 尺寸：`h2D < 25 px`、`25 <= h2D < 40 px`、`h2D >= 40 px`；
- 距离：`Z < 20 m`、`20 <= Z < 40 m`、`Z >= 40 m`。

`h2D` 是 GT 二维标注框高度，`Z` 是 GT 在相机坐标系中的前向深度。不使用预测框高度或预测深度进行分档。

在项目根目录执行：

```bash
python tools/evaluate_bins.py \
  --dataset-root /path/to/KITTIDataset \
  --result-dir /path/to/outputs/monodetr/outputs/data \
  --split val \
  --output-csv /path/to/bin_evaluation.csv
```

自定义分档：

```bash
python tools/evaluate_bins.py \
  --dataset-root /path/to/KITTIDataset \
  --result-dir /path/to/outputs/monodetr/outputs/data \
  --size-bins 0,25,40,inf \
  --distance-bins 0,20,40,60,inf
```

脚本同时输出：

- 各类别、各分档的有效 GT 数量；
- `AP_R40 3D`、`AP_R40 BEV`；
- `Rmax 3D`、`Rmax BEV`。

`Rmax` 是标准 IoU 阈值下 PR 曲线的最大召回率：Car 使用 IoU 0.7，Pedestrian/Cyclist 使用 IoU 0.5。该值不依赖人工选择的单一置信度阈值。

分档时，档外同类 GT 标记为 ignored GT，不删除预测框，因此不会把档外真实目标对应的预测错误计为额外 FP。所有分档都使用同一个 best checkpoint 的同一份预测结果。

## 4. 参数量和计算量

先在训练环境安装 THOP：

```bash
pip install thop
```

使用 KITTI 固定输入分辨率 `1280 x 384`、batch size 1 统计：

```bash
python tools/profile_model.py \
  --config configs/monodetr.yaml \
  --width 1280 \
  --height 384 \
  --device cuda
```

只统计参数量：

```bash
python tools/profile_model.py \
  --config configs/monodetr.yaml \
  --parameters-only \
  --device cuda
```

脚本输出总参数量、可训练参数量、GMACs 和 GFLOPs。其中 GFLOPs 按 `1 MAC = 2 FLOPs` 换算。

MonoDETR 含多尺度可变形注意力 CUDA 算子，SCA-FPN 还可能含可变形卷积；THOP 可能无法计入这些自定义算子。因此论文中应注明统计工具、输入分辨率和 MAC/FLOP 换算规则，并保证 Baseline 与所有改进模型在同一软件环境中统计。如果自定义算子未被计入，应将数值写为“THOP 可统计算子的理论计算量”，不宣称是完整精确 GFLOPs。
